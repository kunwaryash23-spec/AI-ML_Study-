## Concepts touched

## Worth remembering

**You fixed yesterday's leak.** The 2026-08-06 note flagged `sc.fit_transform(X_te)` refitting the scaler on test data. Today every model went through `make_pipeline(StandardScaler(), ...)`, which refits the scaler inside each CV fold automatically. That is the right habit — keep using pipelines instead of manual `fit_transform` calls.

**Bigger is not better.** `(128,)` scored *below* `(64,)`, and `(64, 64)` scored below it too. More capacity on 1797 samples just means more to overfit. The unanswered question in the notebook — "which network would you ship?" — has an answer worth writing down: `(64,)`, because it wins on CV score *and* is the cheapest of the top performers.

**Your MLP lost to logistic regression.** That is not a failure, it is the useful result. On 64 clean, centered, low-dimensional features a linear model is already near-optimal, and the MLP's `early_stopping=True` holds out 10% of training data for validation, so it trains on less. Worth re-running the MLP without `early_stopping` to see how much of the gap that explains.
