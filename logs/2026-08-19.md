### Day 28 revisited — SGD swapped for Adam

`Day_28/Py_torch.ipynb` was re-run rather than extended (+415/−314 lines, same 6 cells).

- The linear fit now uses `optim.Adam(lr=0.001, betas=(0.9, 0.999))` instead of `SGD(lr=0.1)`. Worth seeing what happened: after 200 steps the loss went **3.014 → ~2.4**, which is barely anywhere. The last sync flagged `lr=0.5` as too aggressive; `0.001` on a 50-point linear problem is the opposite error. Adam's default `lr=1e-3` is tuned for deep nets with many noisy mini-batches, not a two-parameter full-batch fit. The lesson is that a "safe default" learning rate is only safe relative to a problem size.

### Day 29 — embeddings, and a sentiment model built from scratch

`Day_29/sentiment_checker.ipynb`

- You built the whole text pipeline by hand instead of importing one: 10 hand-written reviews → a sorted vocabulary → `stoi` (string→id) → `encode()` returning a tensor of ids. Building `stoi` from `sorted({...})` is the right instinct — sorting makes the vocabulary deterministic across runs, so id 16 is always `"the"`.
- `nn.Embedding(num_embeddings=21, embedding_dim=4)` and then the key observation: `embedding(ids)` on a 4-word sentence returns shape `(4, 4)` — one trainable vector per token. **An embedding layer is just a lookup table that happens to be differentiable.** The `grad_fn=<EmbeddingBackward0>` on the printed tensor is the proof: those word vectors are parameters, and the loss will reshape them.
- `vectors.mean(dim=0)` collapses `(4, 4) → (4,)`. That is **mean pooling**, and it is your first sentence encoder. It also has an obvious weakness you should hold onto: averaging discards word order, so `"the movie was great"` and `"great was movie the"` produce an identical sentence vector. Everything that comes later — RNNs, attention, positional encodings — exists to fix exactly that.
- `SentimentNet(nn.Module)` wired it together: `nn.Embedding(vocab, 8)` → `.mean(dim=0, keepdim=True)` → `nn.Linear(8, 2)`, trained with `CrossEntropyLoss` + `Adam(lr=0.05)` for 120 epochs. Loss `0.698 → ~0.001`.

  Note that `0.698` start: that is ≈ `ln(2) = 0.693`, the loss of a model guessing uniformly between two classes. Recognising that number on epoch 0 is a real diagnostic skill — if your binary classifier *doesn't* start near 0.693, something is wrong before training even begins.
