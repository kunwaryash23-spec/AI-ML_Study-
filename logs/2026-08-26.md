### 1. The system prompt — your first real one

`create_agent` accepts a `system_prompt`, and you used it properly:

```python
custom_system_message = SystemMessage(content="""
You are a strict but helpful technical support agent.
...
Always prioritize:
Accuracy → Clarity → Structure → Conciseness.
""")

assistant = create_agent(
    system_prompt=custom_system_message,
    tools=TOOLS,
    checkpointer=InMemorySaver(),
    model=model,
)
```

Seven numbered sections — structure, clarity, code, answers, readability, troubleshooting, tone — ending in an explicit priority ordering. **The priority line is the best part.** Most system prompts are a pile of equally-weighted wishes, and when two of them conflict the model picks arbitrarily. Telling it that accuracy beats brevity resolves the conflict in advance. Keep writing prompts that way: rules, then a tiebreaker.

The one thing to be aware of: a system prompt this long is prepended to *every single turn*. At roughly 400 tokens it is cheap now, but when you start measuring cost per conversation, the system prompt is a fixed tax on every message. Worth knowing before you write a 2,000-token one.

### 2. Four tools, and the difference between them

```python
TOOLS = [search_notes, calculator, decide_for_me, roll_dice]
```

`search_notes` is the interesting one. It is retrieval, built by hand, with the index fitted exactly once:

```python
_vec = TfidfVectorizer().fit(NOTES)          # build the index once
_M   = _vec.transform(NOTES)

@tool
def search_notes(query: str) -> str:
    """Search the user's course notes and return the most relevant note."""
    sims = cosine_similarity(_vec.transform([query]), _M)[0]
    return NOTES[int(sims.argmax())]
```

**You fixed the Day 24 bug and kept it fixed.** `fit()` at module level, `transform()` inside the function — the vectorizer is never refitted per query, so the vector space stays stable. That was the single biggest correctness bug in the early RAG notebooks and it hasn't reappeared in three sessions now.

Two honest limitations to name, since the file is called `rag_agentic`:

- **`argmax()` returns exactly one note, always.** There is no threshold and no top-k. If you ask about something not in `NOTES`, it still returns the least-bad match with full confidence, and the model will answer from it. A `if sims.max() < 0.15: return "no relevant note found"` guard is three lines and turns a confident wrong answer into an honest one. This is the single highest-value edit to this notebook.
- **This is TF-IDF over 6 hardcoded strings, not the Chroma pipeline from Days 31–33.** Which is fine for learning the agent side — but Day 33 already has a persistent Chroma collection wrapped as a `search_pdf` tool that was never handed to a model. Wiring *that* retriever into *this* agent is the natural next notebook, and it would make the folder name true.

`decide_for_me` and `roll_dice` are toys, and that is a legitimate use of a session. They cost five minutes and they teach one real thing: `options: list[str]` becomes a JSON array in the tool schema, so you can now see how the model fills in a non-scalar argument. The empty-list guard in `decide_for_me` is good instinct — tools receive model-generated input, and model-generated input is user input.

`calculator` still routes through the AST-whitelist `safe_eval` from Day 33. Correct, and no `eval()` demo in this notebook. Good.
